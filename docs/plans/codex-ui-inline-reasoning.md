# Codex UI inline reasoning

## Understanding

将用户已确认的 `inline` 原型行为落到正式 codex-ui，修复思考在工具参数生成期间消失、在 `message_end` 后补入并推开工具行的问题。本次迁移显示规则和验收场景，不直接迁移原型 Proxy，也不修改 Pi 上游或全局配置。

参考：`prototypes/codex-reasoning-ui-prototype/src/inline.ts`、`__tests__/inline.test.ts` 及该目录的 README。

## User Visible Changes

- 每段连续思考从第一个完整标题出现时就在原生消息位置显示一行摘要；后续完整标题原地替换，未闭合的新标题不覆盖上一条。长标题截断，不换行；无标题正文不自动充当摘要。
- 生成工具参数、执行工具、消息完成后继续显示同一条摘要，不再补入多条标题或思考正文。取消、失败及恢复会话也使用同一显示规则，原始 session 和模型上下文中的完整思考不变。
- 移除输入框上方的思考状态 widget 及其间距。工具、回复、输入框内部布局和终端标题动画不变；原生 `Ctrl+T` 思考显隐及其占位行为保留。

## How To Test

按以下完成条件逐项执行 Red → Green → Refactor，先确认失败来自行为差距，再修改实现。

### Behavior

- 用真实 `AssistantMessageComponent`、`ToolExecutionComponent` 和生产输入框复现：第一条摘要流式时立即可见；第二条替换第一条且不增加行数；经过 `thinking_end → toolcall_start → 多次 toolcall_delta → message_end → 工具完成`，已显示摘要、工具标题和输入框的行号不因思考显示转换而变化。
- 验证多个连续 thinking 块合并为一行、正文增长不替换标题、空内容、无标题、未闭合标题以及标题中的中英文、emoji、Markdown 标点和终端控制字符。宽度从 120 缩到 60、30 及极窄值时，每段摘要至多一行，输出不越界；相同内容的 streaming/final 显示一致。
- 验证取消、失败、后续消息、树导航、reload 与恢复 session 后摘要不串消息，历史不会恢复完整正文。对比原始消息及持久化 session，确认显示转换没有改写 thinking 或普通回复。
- 验证没有安装思考 widget，没有新增输入框上方的固定空白区；工具内容、回复 Markdown、输入行为和终端标题动画保持原行为。`Ctrl+T` 仍由 Pi 处理，不将用户主动切换显隐导致的重排视为本次回归。

### Performance

本路径会随流式更新和历史重绘高频运行，不能直接把原型每次 `matchAll` 全快照扫描当作生产实现。

- 修改生产实现前，使用当前生产版采集基线并保存源码、运行版本和原始指标。复用 `prototypes/codex-reasoning-ui-prototype/src/bench.ts` 的负载与启动器，不把更早的冻结 `current` 变体当成本次变更前基线。
- 代表负载沿用现有基准：0 条历史、20 条折叠/展开工具历史；每轮 64 帧正文追加或标题更新；长正文使用现有 2500 次段落重复 fixture；另测完成帧、稳定输入及 30 次回放后的内存。每场景 7 轮，前 2 轮预热。增加同一思考块持续追加标题的场景，避免只测替换快照而漏掉真实原地更新路径。
- 将确定性约束写成失败测试：缓存命中的相同内容不重复扫描正文，改变宽度可复用已解析摘要；重复正文更新不主动安装 widget、启动定时刷新或追加可见历史；缓存达到容量后会淘汰，清理后不持有所有历史全文。
- 前后在相同 Node、Pi、终端尺寸和负载下记录渲染 CPU、同步耗时、最大单帧耗时、ANSI 字节、全量重绘次数和 GC 后内存。稳定渲染及输入路径与变更前基线比较，出现可重复退化时定位并处理；新增实时摘要路径单独报告成本，不以功能测试通过代替性能结论。
- 目前没有新增的毫秒级预算，不编造阈值。若基线不足以判断可接受性，记录差异和未决项，不宣称性能已经达标；有界缓存与重复扫描的确定性约束仍须通过。

### Final verification

- 运行 `pnpm run check`，完成类型检查、正式测试、构建和发布包校验。
- 使用默认已安装 Pi 与 `--runtime repository` 分别执行更新后的生产原型 smoke 和真实 CLI/PTY 检查；当前已验证原型的版本为 0.85.1 与 0.84.3，执行时重新记录实际版本。
- 重播标准及长标题场景，检查缩窄、Esc、工具展开、思考显隐、reload 和恢复会话；对固定工具内容比较完成前后布局，不要求正常新增工具或回复时整个终端绝对静止。
- 回归保留的原型入口，清理本次验证启动的进程与临时 workspace，不终止用户自行启动的演示。自动 PTY 结果不替代人工终端体验或 GPU 测量。

## Notes

- 已确认的是 `inline`，不是固定输入框状态行。不要继续将思考从状态栏转移到历史，也不要等待整条 assistant 消息结束才显示摘要。
- 一行对应原生渲染器合并的一段连续 thinking，不是整个会话共用一行；被普通回复分开的思考段仍独立显示。
- Pi 的父容器 Spacer 不在本次修改范围。无标题思考可能仍留下宿主空行；本次通过提前显示摘要消除延迟补入，不承诺删除所有原生间距。
- 原型对括号、方括号和反斜杠标题使用原生代码样式以保留字面量。正式实现须保留字面内容和单行约束；若要改成不同视觉样式，先单独确认。
- 不修改上游、全局安装目录、持久化思考数据或模型请求，不新增通用状态文案。已完成实现与下述验证；提交与推送按用户后续指令单独执行。

## Results

### Implementation

正式入口直接调用 `ReasoningSummary`，不区分 streaming/final，不安装 thinking widget 或思考生命周期状态机。旧组件只在 `fixed` 原型中保留。独立终端标题动画、工具 renderer 和普通回复 transformer 未改。

缓存最多保留 32 个内容条目、合计 262144 个 UTF-16 源字符；超限按 LRU 淘汰，单条超预算不缓存，每条仅保留一个宽度的格式化结果。追加快照替换前一缓存条目，扫描器只保存解析阶段与标题偏移。完整前缀核对后才增量扫描，`startsWith` 与字符串哈希仍可能有全文成本，不能将总路径称为 O(delta)。`session_start`、`session_tree`、`session_shutdown` 清理缓存。相同内容、换宽度、冷缓存、替换和跨消息访问的结果一致。

TDD 首次用正式注册运行原型行号测试，3 项均因流式摘要缺失而失败；接入后通过。重复扫描测试先在每次创建扫描器的实现上失败，再加入缓存。补充容量、超大源、控制字符、每个源前缀的冷暖一致性及稳定输入不调用摘要转换测试。标题截断后再次剥离 TUI 附加的 ANSI reset，避免控制序列被误识别为 Markdown 方括号。
