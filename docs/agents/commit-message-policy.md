# Commit Message Policy

## Scope

本 policy 只适用于 agent 创建的 commit message。

它不约束 git commit 行为本身，包括但不限于：

- 何时允许 commit
- 是否自动 commit
- 是否 amend、squash 或拆分 commit
- 是否运行测试或其他验证
- 是否使用 `git add -A`

如果用户显式提供 commit message，agent 不得擅自改写。若用户提供的 message 与本 policy 冲突，agent 必须指出具体冲突，给出一个符合 policy 的建议版本，并等待用户确认。

commit message 的语言遵循仓库已有 repository language policy 或更高优先级约束；本 policy 不重新定义语言偏好。

## Header

commit message 第一行使用 Conventional Commits 形态：

```text
<type>(<scope>): <subject>
```

`type` 和 `subject` 必填，`scope` 可选。

允许的 `type` 固定为：

```text
feat, fix, docs, test, refactor, perf, build, ci, chore, revert
```

`scope` 可由 agent 从主要变更区域推断，但必须短小、稳定、低熵；无法用一个清晰 scope 概括时省略。

`subject` 应描述本次提交带来的结果，而不是复述文件操作。它必须简短、可扫读，不以句号结尾，不写成完整说明文、测试报告或大段摘要。

Header 应优先控制在 72 个字符以内，且必须控制在 100 个字符以内。如果超过 72 个字符，只能是为了保持清晰；不得把解释、issue reference、测试结果、实现摘要或文件清单塞进 header。

## Body

默认不写 body。只有当 `subject` 无法安全表达必要上下文时，才添加 body。

body 可用于说明：

- 变更动机或重要取舍
- 破坏性影响和迁移方式
- 重要 issue reference
- revert 原因
- 必须保留在 commit history 中的上下文

body 不应复制验证输出、测试日志、diffstat、文件清单或 agent 最终回复式实现摘要。

body 单行应尽量控制在 100 个字符以内；长 URL、路径、表格或其他无法合理换行的内容可以例外。

## Footer

footer 只用于结构化元信息，例如：

```text
Refs: #123
BREAKING CHANGE: rename policy file path
```

issue reference 优先放在 body 或 footer，不强制塞进 subject。

footer 单行应尽量控制在 100 个字符以内；长 URL、路径、结构化 trailer 或其他无法合理换行的内容可以例外。

## Reverts And Breaking Changes

`revert` 类型使用 `revert:`，并必须在 body 中说明被 revert 的 commit 和撤回原因。

breaking change 可在 header 使用 `!`：

```text
feat(api)!: 调整认证响应结构
```

使用 `!` 时，必须同时在 body 或 footer 中解释破坏性影响和迁移方式。单独的 `!` 信息量不足。

## Type Selection

当一个提交同时覆盖多种变化类型时，选择主导 `type`。是否拆分提交不属于本 policy 范围。

`chore` 只能作为最后兜底。优先使用更具体的 `docs`、`test`、`build`、`ci`、`refactor`、`perf`、`fix` 或 `feat`。

## Forbidden Content

commit message 禁止包含：

- AI 生成或协助说明，例如 `Generated by Codex`、`assisted by AI`、`implemented with AI`、`reviewed by AI`
- 自动协作者署名或 AI 署名，例如 `Co-Authored-By: ...`，除非用户显式要求或更高优先级规则要求
- 验证输出、测试日志、diffstat、文件清单
- agent 最终回复式实现摘要
- token、secret、私有 URL、用户个人数据、内部凭据、环境变量值等敏感信息
