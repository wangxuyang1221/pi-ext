# Subagent runtime reliability todo

## Understanding

本轮一次性交付审查问题 1–6：存活与定位混淆、跨进程状态覆盖、会话切换容量空窗、全局状态故障扩散、child 环境不确定，以及超时和取消无法穿透底层查询。采用单写者状态拆分、进程级名额、证据化关闭和有界 I/O，保留 tmux 与 Pi 原生 JSONL。

已同意调整 Extension 状态格式，不支持旧 child 在线热升级。实现已落地；勾选表示对应实现及已有验收通过，未勾选项仍缺少原计划的完整验证，不表示没有代码。准确范围见 [acceptance record](subagent-runtime-reliability-acceptance.md)。

## User visible changes

- 身份不明、查询失败或关闭未完成时，保留 child 管理关系与名额并提供具体诊断；不再将这些情况报告为已退出或关闭成功。重试关闭可以继续已有进度。
- child 切换会话不释放名额；确认无关的损坏或旧版状态不再阻断当前 namespace 的管理。当前记录异常仍保守占位，不悄悄遗忘 child。
- child 使用明确的父端有效配置，不受旧 tmux server 配置干扰。登记时发现身份、协议或必要配置不一致，会在初始任务投递前失败并进入受控清理。
- wait 能超时、取消，且不会因此终止 child。spawn、prompt 的结果无法确认时保留操作身份，不自动重试；close 超时或取消后保留关闭意图。
- 同一 namespace 只允许一个有效管理控制者；其他实例仍可只读查看。升级前必须受控关闭旧 child、停止旧写入者，无法核验的旧对象不得自动迁移或删除。

## How to test

### Investigation and baseline

- 先将已确认的反例写成直接调用仓库源码的失败测试，再按对应实现项执行 Red → Green → Refactor；不把转录源码的探针当成回归测试。
- 实现前使用隔离夹具核验 Pi 0.84.3 与 0.85.1 的事件顺序、真实 tmux 定位和命令终止行为。测试未知身份的保守路径，不能只覆盖正常退出。
- 当前 `SessionStateStore.list()` 全盘加载状态，manager 多条路径重复扫描；`session-reader.ts` 全量读取 JSONL，输出字节上限不等于读取和解析耗时有界。调查需明确必须保留的结果成本与可以消除的重复 I/O，并据此选择实现。
- 超时验收分别记录操作预算、清理宽限和调度容差。实施前结合终止升级方案及隔离实验确定固定上限，再写成断言；不能用第一次实现的实测耗时反过来定义合格标准，也不承诺硬实时返回。

### Target behavior

| Problem | Trigger | Required result |
| --- | --- | --- |
| 1 | 真实 tmux 改名、移动、server 重启、PID 不匹配、查询失败、保留 dead pane、关闭中重启 parent | 不关闭错误对象；无退出证据不成功、不释放名额；有充分身份证据时能更新位置；资源清理可重试 |
| 2 | 两个真实 OS 进程交错执行关闭与 settled，控制权竞争、reload 旧回调、写入中断、删除后迟到登记 | 已确认的完成事实不回退；旧控制者不能写入或继续破坏性操作；终结关系不复活；原生 JSONL 保留 |
| 3 | 在旧会话关闭与新绑定保存之间设置屏障并发 spawn，启动各阶段终止 parent，迟到注册与 `close all` 并发 | 进程名额不因切换变化；预留不超卖；TTL 不遗忘结果未知的启动；关闭过程不丢受管进程 |
| 4 | 无关 namespace 与当前 namespace 分别出现损坏 JSON、旧版、未来版本和权限错误 | 无关错误不阻断健康 child；当前错误保留占位并给出诊断；未知版本不被覆盖或当成空记录 |
| 5 | 经生产入口连接预先带旧环境的 tmux server，测试父端新配置或未设置值、绝对程序路径不在 PATH、多 server | child 有效配置与启动契约一致；不复制父 pane 身份；不一致时初始任务未发送；日志和状态不泄露凭据 |
| 6 | 底层查询挂起、延迟、忽略 SIGTERM，长 JSONL 读取期间取消，server 已执行变更但响应未返回时取消 | wait 在约定预算与宽限内返回，child 不被误杀；查询进程、定时器及临时资源不遗留；结果未知保留身份与名额、不自动重发 |
| Upgrade | 旧写入者存活、旧记录损坏、离线转换中断、升级后回退 | 拒绝不安全转换并保留原始记录；可验证的离线升级与回退可重复执行；原生 JSONL 内容不变 |

还须保护既有契约：root → direct child、空闲 child 占名额、共享进程 alias 去重、历史 alias 删除不杀当前进程、`settled` 不等于任务成功、receipt 区分未消费队列与已完成投递、快速完成不误判，以及已有活动分页和输出上限。第 7 项的归属切换逻辑与 token 公式不在本轮调整，但现有 usage 测试必须继续通过。

### Performance and resource acceptance

- 固定当前 namespace 的进程、预留和 alias 数，分别添加 0、100、10,000 个无关 namespace。普通 list/read/prompt/close 不读取无关状态、不触发全局扫描，相关文件访问次数不随无关记录数增长。这由作用域索引能够达到，不以旧实现耗时作为门槛。
- 以当前 namespace 的进程数 P、预留数 R 和 alias 数 A 检查工作量。完整列表允许必要的 O(P + R + A) 工作及结果存储；同一轮探测按进程去重，不能随 alias 数重复查询 tmux。关闭确认的有界重试另计，不与首次去重混淆。
- 连续超时、取消和重复轮询后，命令进程、监听资源及待执行查询不累积。每次等待只允许受控数量的在途查询，不采用无限 `Promise.race` 遗留底层任务。
- 以不同大小的 JSONL 检查取消延迟和解析阻塞。长读取不能耗尽外层取消机会；同一快照的结果裁剪不应重复全量读取。保留已有 cursor、分支可见性与输出预算，禁止以截断历史改变结果语义。
