## User Visible Changes

- 常规 Pi CLI 使用全局及受信任项目的文件配置时，启用 codex-ui 后，Bash 保留命令前缀和指定 shell，Read 遵守图片自动缩放设置；此范围同时覆盖 TUI、print 和 RPC。会话内修改文件配置后，通过 `/reload` 应用，不承诺实时同步宿主内存配置。
- CRLF 文件的 Write diff 不再被回车和补齐空格擦空，文件中的终端控制序列不能控制 diff 区域的光标或清屏。
- 用户消息的 `›` 标记改为独立段落，会增加一行标记及段落间距；首行代码围栏、表格、列表和标题按原 Markdown 结构显示，代码字面量不再被当作强调语法。
- 默认扩展顺序下，空闲时手动发起 Codex compact，标题动画在等待压缩期间启动，并在成功、失败或取消结束后停止。
- 窄终端中，单字符项目目录也能降级显示截断 Git 分支，不再因等宽中间变体隐藏整个 location。
- 出现重复 Bash 调用 ID 时，显示仍保持源码顺序，不跨 text、thinking、其他工具或消息边界分组。

### Cost And Resource Checks

## Accepted Compromises

- 问题 1 只保证常规 CLI 文件配置兼容，不保证自动获得 SDK 内存覆盖、自定义 settings 存储或宿主自定义执行器。需要这些能力的 SDK 调用方必须显式提供 factory/config；未接入时不能假定插件会自动保持宿主执行语义。
- 问题 4 保留当前 Read 分组。接受 Ctrl+T 等历史重建后降级为独立显示，普通重绘不能恢复；恢复方式为 `/reload`，已通过真实 SDK reload 和历史组件重建验证。此项是用户接受的已知显示限制，不是修复结果。
- 不采用宿主内部兼容层、原型补丁或宿主源码修改，也不取消 Read/Bash 的现有 Codex renderer。不为达到原清单的完整 SDK 兼容或历史重建分组要求而扩大范围。
