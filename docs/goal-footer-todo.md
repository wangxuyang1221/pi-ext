# Goal Footer Todo

## Understanding

将已认可的 goal footer 原型接入正式 goal extension：常驻摘要只显示分钟，详情提供精确到秒的打开时快照，不引入秒级刷新。沿用既有计时、预算和目标状态转换规则，不把原型代码直接作为生产实现。

参考原型：`prototypes/goal-footer-prototype/README.md`。界面状态与操作提示使用英文，目标保持用户原文。

## User Visible Changes

- 原来的状态、token、秒数串改为两行目标摘要：第一行显示目标，第二行显示状态、分钟耗时和 token 用量。有预算时显示用量与预算，无预算时只显示用量。长目标截断。
- Footer 显示 `<1m`、`12m`、`1h 05m` 等分钟级耗时，仅跨累计耗时的分钟边界时主动刷新时间；状态和用量变化仍立即更新。
- `/goal` 从通知改为详情面板，显示目标、状态、精确耗时和用量。精确耗时在打开时读取，不逐秒变化，关闭后重新打开获取最新快照。暂停、恢复复用现有行为；关闭面板不暂停任务。

## How To Test

### Before Implementation

先按下面的行为逐项写失败测试，再实现并执行 Red → Green → Refactor。

实现前，在仓库锁定的 Pi 版本、相同终端尺寸与主题下，采集无时间主动刷新和分钟边界刷新的对照。使用 0、500、2000 对历史消息，区分空闲、工具等待和流式输出；记录 Pi CPU、终端 CPU、每次刷新耗时与输出字节数。CPU 绝对阈值由定位阶段结合候选实现、重复测量波动及可避免开销确定，不能直接把旧实现或首次实现的表现当作合格线。

### Behavior

- 验证 0 秒、59→60 秒、12m 59s→13m、59m 59s→1h 00m。模拟延迟回调，显示按基准追上实际时间，不逐 tick 累加。
- 验证跨分钟、入账和暂停同时发生时不重复累计；恢复从冻结值继续。预算收尾、目标替换、重载和会话恢复的耗时语义与原实现一致。
- 验证 `/goal` 打开时的精确值；等待数秒后保持原快照，重新打开更新。面板打开期间目标被清除、替换或会话发生变化后，旧面板操作不能作用于新目标。
- 覆盖无预算、无目标、用量不完整、预算限制、blocked、工具缺失、存储与内容读取失败，保证必要诊断没有因新布局丢失。
- 真实 PTY 覆盖 regular/fullscreen、40/80/120 列、中文长目标、主题切换、暂停/恢复、完成和清除。分别启用与停用 codex-ui；既有 footer 信息和其他扩展的状态不丢失。

### Performance

- 用可控时钟验证：从整分钟开始，连续计时 10 分钟恰有 10 次计时器回调，不计初始化与外部事件。分钟内没有时间驱动的刷新请求，暂停或完成后没有计时器；重复切换目标和会话不会叠加定时器。
- 对显示路径加调用计数断言：计时 tick 不调用存储读写、锁核验、内容包读取或会话历史扫描；分钟未变时，普通重绘复用 goal 行缓存。区分新增显示逻辑与 Pi 自身组件树遍历，不把终端差分输出当成无 CPU 成本的证据。
- 在相同负载下重复实现前的对照，按定位阶段确定的标准验收 CPU 与刷新耗时。高开销若来自本次路径，须处理后才能完成对应实现项；未能测量真实终端 CPU 时明确保留该限制。
- 复用原型 PTY 设施检验分钟内静止界面无周期输出；这个检查只验证是否持续刷屏，不代替 CPU 测量。
