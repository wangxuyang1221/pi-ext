# Pi 0.86.0 Compatibility Todo

## Understanding

将 pi-ext 的开发、测试和构建依赖统一到 Pi 0.86.0，修复已确认的压缩历史兼容问题和用户消息空行问题，并检查全部已注册扩展受升级影响的路径。验收包括旧会话恢复，不以新建会话正常或类型检查通过代替兼容性验证。

## User Visible Changes

- 已有压缩 checkpoint 的会话遇到提示或工具变更后，仍能在工具执行完成后继续请求，不再因本次历史转换缺口连续出现 `Operation aborted`。
- 用户消息保留灰色背景和原始 Markdown，取消插件注入的 `›` 及其额外段落空白；用户自己输入的 `›` 保持原样。
- 其余扩展保持既有行为。目标运行与验收版本为 Pi 0.86.0，其他版本的支持范围须由兼容性调查明确。

## How To Test

- 实施顺序：行为修改前读取 develop-with-tdd skill，按 Red → Green → Refactor 推进。先在当前依赖下采集全仓失败基线，再在 0.86.0 下比较；记录环境与失败用例，不能直接沿用交接中的失败数量。
- 压缩直接回归：使用合成历史构造“旧 checkpoint → system 更新 → 首次用户请求 → 工具返回 → 下一请求 → 失败用户重试”，核对每一步的完整请求结构、顺序与 checkpoint 保留。分别覆盖仅提示更新、仅工具变更、组合更新、工具移除，以及消息 ID 和相关工具声明格式。与目标版本上游转换结果对照，避免仅验证插件自己的预期。
- 保护与诊断：历史确实不匹配时仍应阻止错误请求；会话或模型切换的取消行为保持正确。诊断可定位失败阶段，且不包含敏感正文或认证信息。
- UI 直接回归：比较完整渲染行及高度，不过滤空行或 marker 行。覆盖普通文本、空文本、用户自带 `›`、窄窗口换行、标题、列表、表格、代码块及混合内容，并核对重复渲染和更新后的结果。
- 全扩展集成回归：依据调查结果选择现有测试和 smoke 入口，至少核对会话恢复及分支、模型切换、工具注册与调用、MCP 工具变化、权限允许与拒绝、subagent 生命周期、goal 恢复与事件处理、Fast Mode 请求选项和 UI 渲染。记录哪些使用真实 0.86.0 宿主、哪些仅使用 mock，未验证路径明确保留为缺口。
- 性能验收：优先使用调用或扫描次数断言，检出按每条历史重复扫描全量历史、重复构造工具表等可避免开销；用不同历史规模核对调查确定的增长约束。UI 延续“更新单条消息不重新转换未变历史”的检查。没有依据时不设任意毫秒阈值。
- 事故重放：构建后运行 `node .tmp/codex-compact-incident/replay.mjs`，确认原先失败分支通过。该脚本仅作本机只读辅助证据，正式回归使用合成数据，不提交私有会话 fixture，不写原始会话。
- 最终检查：使用 `pnpm install --frozen-lockfile --ignore-scripts` 验证锁文件安装，然后运行定向回归及 `pnpm run check`。若全量测试阻断后续步骤，仍单独执行 `pnpm run build` 与 `pnpm run package:check` 以获取结果，但不得据此标记全仓检查通过。
- 完成判断：各扩展受影响路径已审查，直接回归与必要集成检查通过。升级引入的失败必须解决；既有失败须有归属依据及影响说明，不能统一归为基线后忽略。存在相关未验证项时，对应实现项保持未完成。
