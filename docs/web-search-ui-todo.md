# Web search UI implementation todo

## Understanding

将用户已认可的 [动态原型](../prototypes/web-search-prototype/README.md) 接入正式 Web Search renderer，采用两行默认视图、原生展开和 codex-ui 状态样式。迁移已验证的布局决定，不直接搬入原型执行器或 fixture 数据结构。

## User Visible Changes

- 默认显示动作标题、首条查询及剩余查询数，下一行显示进度或结果摘要；完整查询列表、运行配置和来源移到原生展开视图，不再默认显示查询树、配置标签和独立完成对勾。
- 使用 codex-ui 的静态 `⏺`、主题语义颜色和缩进。进度原位更新，相邻搜索块之间从三行空白减为一行；窄窗口优先保留失败状态和关键计数。
- 成功、部分失败、全部失败、超时、中断分别显示准确状态。部分失败不再呈现为全绿成功；成功但零来源仍区别于失败。沿用原型的英文 UI 文案及 Pi 当前工具展开快捷键。

## How To Test

按下列行为逐项先写失败测试，再实现并回归。常规测试、快照和验收记录属于对应实现项的完成条件，不另作功能任务。

- **调查验证**：确认实际扩展 provenance、Pi 版本、构建入口和 renderer 注册；复用 [空行调研](../.scratch/docs/research/codex-search-tool-row-spacing.md) 与当前源码核对宿主边界。检查真实 progress/result 的结构和错误类型，不能根据原型 outcome 推断生产分类。
- **默认布局**：单查询、五查询及连续两次搜索默认各占两行，标题与结果之间无空行；相邻搜索只有宿主的一行空白。检查 `+1 query` 单复数、中文、长查询、流式参数未完整等情况。
- **状态回归**：覆盖等待、运行、多次进度更新、全部成功、零来源、部分失败、全部失败、真实取消、超时和未知错误；错误文案不得靠宽松字符串匹配误分类。对旧 session 缺失 details 的记录验证降级，不显示虚构的成功、来源数或耗时。
- **展开与主题**：Ctrl+O 或用户重绑定的工具展开快捷键能显示完整查询、配置、诊断和已有结果；收起恢复两行。验证 codex-pi/浅色主题、regular/fullscreen、40/80/120 列以及更窄宽度上限。所有输出行不得超过传入宽度，终端控制字符不得污染界面。
- **契约保护**：以真实执行器的离线边界 mock 验证取消与失败，不触发付费请求；检查返回正文、排序、错误标记、重试和取消行为未变。验证不启用 codex-ui 时搜索扩展仍能加载，Standalone 共用路径没有被改成搜索专用文案或丢失原有预览。
- **性能验收**：用 fake timers 和 invalidate 计数确认没有搜索专用周期重绘；无新事件的 held 搜索不产生主动更新，结束后无残余 timer/listener。用递增来源/正文规模及重复同宽渲染、缩放验证折叠态不重复扫描全量结果。允许新结果到达时进行一次摘要聚合，后续布局工作应随可见行宽而非完整正文大小增长；不要求返回结果本身占用恒定内存。
- **真实 TUI 验收**：在正式 renderer 模式下重放成功、部分失败、超时、取消、连续调用，观察与原型一致的密度；验证取消后可再次运行、reload/历史恢复状态正确，退出后清理本次启动进程和隔离目录。
- **最终验证**：执行搜索扩展自身的类型检查和相关测试，以及 `pnpm run prototype:web-search:check`、`pnpm run check`。如果根检查仍未覆盖搜索扩展，不能以根检查通过代替其独立验证。记录命令、通过结果、未通过项及未验证范围，对应实现项在相关验证完成前保持未勾选。
