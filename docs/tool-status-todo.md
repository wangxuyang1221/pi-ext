# Tool status todo

## Understanding

将用户认可的最后一版原型接入正式 Bash、Read、Edit、Write 和 MCP 工具调用界面。采用大圆点 `⏺` 与原 Bash 的亮灰正文，保留各工具原有布局及执行行为。

参考原型：[Tool status prototype](../prototypes/tool-status-prototype/README.md)。正式实现已完成，验证结果及既有阻塞见 [Tool status acceptance](tool-status-acceptance.md)。

## User visible changes

- 五类工具统一使用静态 `⏺`，后接一个空格，标题加粗。参数生成、已有可见等待态与执行中统一用黄色，成功用绿色，失败用红色；能可靠识别的中断、超时用黄色并保留诊断文字。不新增原来隐藏的等待行。
- Bash、Read、MCP 的正常结果正文统一为原 Bash 的亮度，当前 codex-pi 主题为 `#d6d6d6`，展开与折叠一致。行号、目录、连接线和截断提示仍弱化，文件名强调色、错误警告色及 diff 增删色保留。
- Batch 沿用原生布局。Read 保留分组与 Ctrl+O 展开，各文件独立显示状态；Bash 仍逐条显示命令和输出，Edit、Write、MCP 保留相邻调用，不新增折叠卡片。状态随真实执行事件变化，不增加旋转、闪烁或定时动画。

## How to test

- 实施前按以下目标行为先写失败测试，再执行 Red → Green → Refactor。生产测试直接覆盖正式 renderer，不以原型的源码替换测试代替。
- 验证五类工具在参数未生成完、参数完整但尚未执行、执行中均使用黄色；同时覆盖成功、失败、部分输出后失败，以及真实中断和超时。结果正文含有类似取消的普通文字时不能误判；无法可靠识别的错误仍显示红色。仅替换左侧状态标记，不修改 Bash 输出中的测试勾号或 Read 展开箭头。
- 验证同组混合成功、失败与中断，特别是首项成功、末项中断；覆盖乱序完成、重复调用 ID、分组边界、折叠展开和历史重开。分组按原有调用顺序形成，不能按完成顺序重排，错误诊断和部分输出不能丢失。
- 真实 PTY 覆盖 regular/fullscreen、完整/低功耗、40/80/120 列、中文长路径与主题切换。断言 glyph 占一列、间距一致，Bash/Read/MCP 正文同亮度且辅助信息仍弱化。另验 MCP 不加载 codex-ui 时仍能独立显示；保留参数脱敏与结果截断行为。
- 性能验收使用静止执行态、流式结果及 1/3/20 项分组，分别搭配短结果与长结果。用可控时钟断言本次样式逻辑新增零计时器、零周期刷新；用调用计数检查普通重绘命中已有结果和 diff 缓存，新增状态映射不扫描正文或会话历史。主题或 member 变化后允许必要的失效与重排，不要求消除原有组遍历。依据是固定 glyph 与颜色选择只需读取当前状态，成本不应随结果长度增长。
- 运行相关单元测试、正式代码的 PTY 验收及 `pnpm run prototype:tool-status:check`。若正式代码调整导致原型替换锚点失效，更新原型适配，保留同一视觉方案和 fixture 隔离。静止画面或 PTY 输出不能代替真实终端 CPU 测量，不据此承诺零 CPU 开销。
- 最后运行 `pnpm run check`，预期类型检查、测试、构建和发布校验全部通过。记录结果及无法完成的验收，相关实现项未满足完成条件时保持未勾选。
