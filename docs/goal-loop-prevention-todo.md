# Goal loop prevention todo

## Understanding

修正 goal 完整提醒的投递时机，并增加独立的工具调用级循环保护，避免工作完成后持续重复核验。按“提醒时机修正、循环保护、对照验收”推进，不重写 goal，不扩大 provider 支持范围。

依据：[Codex 对比报告](./research/codex-goal-loop-comparison.md)。真实 session `01a088e7-b52a-768a-afd1-ecba0bd96e1c` 在报告最后一次修改后连续产生 178 次成功只读调用，全部为 `toolUse`。已证明当前调度差异，尚未通过模型 A/B 证明它是唯一诱因。用户随后授权按本清单执行 TDD，不再切片；新增产品文案沿用英文。实现与验收结果见 [Goal loop prevention report](./goal-loop-prevention-report.md)。

## User Visible Changes

- 模型在一轮工作中读取、修改和检查时，不再每一步都收到新追加的完整完成审计；开始或自动续跑一轮时仍收到目标提醒，目标修改和预算耗尽各有一次专用提醒。
- 出现可识别的重复无进展调用时，先提醒模型收尾或改变方法；继续重复则暂停 goal、显示原因并保留目标与统计，用户可用 `/goal resume` 恢复。程序不自动声称完成，也不把模型空转归为外部阻塞。
- 正常只读研究、已核实仍在运行的任务轮询和用户补充指令不应被误停；完成、手动暂停、预算与错误停止等既有行为保持。

## How To Test

执行各实现项时采用 Red-Green-Refactor。先写对应失败测试，再实现；以下为完成条件，不另拆常规测试 Todo。

- **变更前基线**：在修改 scheduler 前，用现有 runtime 记录工具结果和用户催促后的完整模型上下文。复现每请求末尾追加审计，以及重复成功调用不能停止的行为；保存版本、输入序列、消息位置、请求数和用量口径。
- **提醒次数与顺序**：同一工作轮次包含多次工具调用时，完整提醒仅投递一次，工具结果后不重新追加；正常结束且 goal 仍 active 时，下一自动轮次投递一次。用户 steer/follow-up 不被旧审计尾插覆盖；编辑和预算提醒分别只投递一次；重试不重复投递，压缩后保留必要目标信息但不恢复每请求尾插。
- **循环保护**：在阈值前后验证同调用重复和 A/B 交替，预警只发一次，持续重复在契约规定的有限调用数内暂停。用 178 次候选序列证明无需等 `agent_end` 即可拦截；预警后调用 `update_goal(complete)` 或获得新证据时不得被旧计数误停。
- **误停负例**：不同文件的连续只读研究、同参数但返回新证据、已确认活跃 handle 的合法等待，以及等待结束后继续工作均应通过；不能仅凭工具成功或任意文本变化宣称进展，也不能把所有轮询永久豁免。
- **状态与并发**：暂停原因可见，目标与统计保留，`/goal resume` 可继续；手动 pause、complete、预算耗尽、终态错误优先级保持。覆盖并行工具批次、旧事件晚到、目标替换、reload、切换与 fork，不让旧计数污染新目标或未完成工具绕过暂停。
- **用户输入保护**：预警与暂停期间排队的用户输入和其他扩展消息不被新逻辑静默丢弃；保留现有 C11/C12 的已接受范围，不以新增保护扩大其副作用。实际 PTY 验证暂停、提示、恢复与用户催促的可观察行为。
- **确定性成本**：每次工具完成仅更新有界窗口，不遍历全部会话、不重读工作区验证结果、不为每次调用增加远程模型请求；窗口满后条目数与存储字节受契约上限约束，不长期保留完整输出。
- **性能测量**：复用 runtime，使用真实案例的 178 次序列、超过窗口容量的长序列及达到工具输出截断边界的结果，记录单次处理耗时、累计耗时和内存。相同 Node/Pi 版本与输入下重复测量，对比变更前基线；确认每次处理成本不随历史轮数增长。数值预算在契约阶段根据基线确定，不虚设毫秒阈值。
- **模型对照**：固定模型、任务、初始上下文和配置，分别运行旧行为、仅修投递时机、修正时机加保护三个版本，重复观察完成率、重复调用数、用量和误停率。目标是稳定收尾且不误停正常任务；在运行前确定样本与通过标准。离线脚本模型只证明调度，不能代替真实模型效果证据。
- **最终验证**：运行 `pnpm run check`，并复用 Pi 0.84.3/0.85.1 的 runtime、lifecycle、预算和真实 PTY 回归；类型、测试、构建、发布包及既有 C11/C12 场景通过。未执行的真实模型对照必须明确列为证据缺口，不能宣称已验证消除循环。

## Notes

- 用户已授权实现，不再按切片推进。默认窗口 32、连续重复 4 次预警、8 次进入暂停候选，依据原始记录和负例离线校准；这不是通用误停率或语义进展保证。
