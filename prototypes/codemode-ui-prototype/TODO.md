# Codemode call tree implementation

## Understanding

用户已选定方案 2：将 codemode 显示为父节点，内部工具调用按开始顺序排列，展开后显示原有工具内容。保留六个原型共用的 `/inspect` 面板，不采用混合方案，也不把布局切换器带入生产。

生产实现及验收已完成。以下保留原计划和验收要求，完成结果见 [Codemode validation](../../docs/codex-ui-codemode-validation.md)。

## User Visible Changes

- codemode 工具行使用调用树。收起时显示前 5 个子调用摘要及剩余数量，展开后显示子调用详情；Read、Bash、Edit/Write 沿用现有展示和 diff。子调用位置按开始顺序固定，不因完成先后而跳动。
- 父脚本状态与子调用状态分别显示。脚本捕获内部失败并正常结束时，仍保留失败提示；脚本失败、中断、超时或历史记录缺失不能显示为全部成功。脚本输出与子工具原始结果分区显示。
- `/inspect` 打开当前分支最近一次 codemode 执行，保留 Calls / Script / Output 三个视图、宽屏分栏及窄屏详情。使用现有工具展开快捷键，默认通常为 `Ctrl+O`。没有记录或详情缺失时明确说明，不猜测执行结果。

## How To Test

### Investigation

- 实施前核对并复用原型中的真实 QuickJS 场景；通过真实事件检查 `/?` 到正式 ID 的变化及父子终态顺序。补查真实超时、权限拒绝、模型辅助调用和多层嵌套的可观测数据，避免把原型的一级工具调用假设当作通用契约。
- 使用 24、256、1024 个调用元数据及 1 KiB、1 MiB 子输出评估增长成本。区分实时记录与宿主持久化截断，不声称恢复超过宿主上限的信息。根据可见内容需求和项目缓存预算确定原始结果保留上限，记录预算及淘汰行为后再实现；耗时阈值不能直接使用首次实现的成绩。

### Behavior

按 Red → Green → Refactor 推进对应实现项，先写失败用例，再改生产代码。

- 调用树：乱序完成时顺序稳定；临时 ID 不重复计数；0、1、24 个子调用的收起/展开正确。第 6 项失败时，收起态仍显示警告；失败项数量很多时使用有界摘要和明确数量，可在详情查看。
- 状态：覆盖全部成功、脚本捕获子失败、脚本自身抛错、真实中断、真实超时、权限拒绝、无输出及缺失记录。验证已完成文件修改不因后续失败而被 UI 暗示为回滚。
- 子工具与面板：验证 Read/Bash/Edit/Write 的现有内容和 diff，未知工具 fallback、子调用原始结果与父输出分离、Calls/Script/Output 切换、选择与滚动、无记录提示。多层调用保持实际父子归属，不混进其他 codemode 行。
- 生命周期：保存并重启会话、切换分支、reload、compaction 后重建当前分支。历史只有元数据时显示缺失提示，不重现来自旧分支或缓存的正文；关闭面板及会话后不残留监听或后台刷新。
- 终端：普通/全屏模式下验证 40/80/120 列、中文长路径、多行错误、ANSI 控制字符、长 JSON、主题切换及低功耗模式。每个返回行符合可用列宽，不把嵌入换行当成单行交给 TUI；既有工具不出现重复行或跨父调用分组。

### Integration

- 输入链路使用离线 provider 发送真实 codemode 调用，经过真实 QuickJS、工具参数校验、权限 hook、嵌套执行事件及生产 codex-ui renderer，最终在 PTY 屏幕和持久化会话中检查行为。
- Read/Edit/Write 使用临时工作区，Bash 可使用明确标注的结果 fixture；另用本地无副作用命令验证真实 Bash 非零退出和取消。MCP 使用本地测试服务，不依赖生产网络。不能仅向 renderer 注入固定 `details.calls` 就认定集成通过。
- 原型测试仅可作为对照。六布局切换测试不属于生产验收；将方案 2、统一面板和错误行为的有效断言迁入 `extensions/codex-ui/__tests__/`，补上原型未验证的生命周期与生产路径。

### Performance

- 用调用计数断言：相同内容、宽度、主题和展开状态下重复渲染，不重新解析或高亮正文；更新一个子调用不重新准备其他子项的正文。允许更新父摘要，不允许扫描整个会话。
- 增大隐藏调用数量时，收起态最多准备前 5 项摘要及有界警告，不准备隐藏正文。检查面板切换调用只准备新选中项；滚动相同内容复用已准备结果，而非重复全量折行。
- 按调查阶段确定的字节/条数预算，连续运行和切换分支，断言原始结果与布局缓存均不超过各自预算；淘汰不改变执行状态，缺失内容有明确提示。该预算约束 UI 额外保留的数据，不要求 Pi 原始会话记录大小恒定。
- 在同一 Node/Pi 版本下记录上述负载的冷/热渲染耗时与保留数据量。确定性成本约束、预算断言和行为回归均通过后，对应实现项才能完成；发现异常不能只登记为限制后勾选完成。

### Final Verification

- 运行相关 codex-ui 单元测试、生产 renderer 的真实 SDK/PTY 集成检查及 `pnpm run check`；区分通过、跳过和未覆盖项。
- 验证未改变 codemode 的工具声明、权限、执行结果、模型可见输出或会话成本；UI 不增加模型请求或网络请求。
- 记录验收结果，停止本次启动的进程，确认本地测试服务端口已释放。全部专项与仓库检查通过后已勾选上述 Todo。

- 正式入口只启用方案 2；统一 `/inspect`、低功耗和分支恢复已接入。
- `pnpm run check` 通过，2703 项通过、13 项仓库既有条件性测试跳过。
- `pnpm run codemode:check` 通过，包含 17 项专项测试、真实 QuickJS/本地 MCP、普通及全屏 PTY、24/256/1024 项预算与性能检查。
- `pnpm run prototype:codemode-ui:check` 通过，六个原型仍可对照查看。
- 未调用付费分类器或图片服务；这些调用的状态合并有单元覆盖，专属展示仍不纳入。宿主未提供最终子状态时显示 unknown，不猜测为成功或取消。
