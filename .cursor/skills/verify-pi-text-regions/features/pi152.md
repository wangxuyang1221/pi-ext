# Pi 1.5.2 profile

本 profile 验证独立的 1.5.2 补丁宿主。范围为摘要、区域 API、codex-ui Working/速率与宿主交互。运行树显式加载 codex-ui、codex-compact、openai-fast-mode、mcp、skill-mentions。根默认依赖为原版 1.5.2。

## Prepare and identity

在仓库根目录运行。`prepare/build/types/run/doctor` 自动将子进程的 HOME、缓存和临时目录隔离到仓库 `.tmp`，退出时删除本次临时环境。安装使用持久目录 `.tmp/pi152-package-store`，不读取用户 pnpm 配置。准备命令会清除运行树旧源码、主题及 dist，保留 node_modules 和 `.tmp` 证据，因此准备后必须重新 build。

```bash
node scripts/pi152-patched-verify.mjs prepare
node scripts/pi152-patched-verify.mjs build
node scripts/pi152-patched-verify.mjs types
node scripts/pi152-patched-verify.mjs run node test-support/pi152/load.mjs --patched
node scripts/pi152-patched-verify.mjs doctor
```

`host-proof.json` 必须证明四包为 1.5.2、所有内部 Pi 依赖来自同树、两个补丁包路径含 patch hash、源码/主题与锁 hash 一致。启动器核对已安装锁中的精确补丁 hash、内部依赖来源及补丁文件，使用包 manifest 声明的 bin。doctor 检查四包、实际 bin、双模式 API 及消费树的 manifest/workspace/lock/patch hashes。实际 CLI 能力由下面的 PTY 证明。

新目录重放用 `PI152_RUNTIME=.tmp/<new-directory> node scripts/pi152-patched-verify.mjs prepare`，只接受不存在、空目录或身份匹配的运行树；非空未知目录及含符号链接的路径会在清理前拒绝。运行树包含自己的 patch 相对路径及 lock，不依赖旧 node_modules。原版用 `PI152_RUNTIME=.tmp/<new-stock> node scripts/pi152-verify.mjs prepare`，随后同变量 build 和 run load，省略 `--patched`。原版入口严格要求无 patch 路径、无区域 API、无摘要注册。

## Drive

`run` 在对应树解析源码和依赖，证据目录因此位于该树的 `.tmp`。每次给新名字，保留失败记录。以下命令的 `--mode` 分别取 regular、fullscreen，两模式均运行。

```bash
node scripts/pi152-patched-verify.mjs run conda run --no-capture-output -n codex-py312 python scripts/local-refresh-pty.py .tmp/regions-regular --cli node_modules/.bin/pi --mode regular
node scripts/pi152-patched-verify.mjs run conda run --no-capture-output -n codex-py312 python scripts/local-refresh-pty.py .tmp/working-regular --cli node_modules/.bin/pi --mode regular --working --profile pi152
node scripts/pi152-patched-verify.mjs run conda run --no-capture-output -n codex-py312 python scripts/local-refresh-pty.py .tmp/kitty-fullscreen --cli node_modules/.bin/pi --mode fullscreen --kitty
node scripts/pi152-patched-verify.mjs run pnpm test test-support/__tests__/local-refresh.test.ts test-support/__tests__/pi152-upstream.test.ts extensions/skill-mentions/__tests__/session-summary.test.ts
```

fullscreen 的 `/fixture-document` 在真实消息文档中挂载登记组件，延迟局部请求把 revision 0 改为 1。TTY 搜索要求新正文命中 `1/1`、旧正文显示 `No matches`，真实 SGR 拖选的反色单元格文本必须等于最新正文；不写系统剪贴板。

regions 覆盖双向切换、独立/合并更新、编辑/overlay、滚动、真实 TTY 搜索和鼠标选择、图片回退。Working profile 使用 `Status:` 中性行，保留真实 stream、速率、编辑、overlay/input、shell 副作用、Esc 取消、retry、compaction、new/reload。Kitty 检查传输字节。物理像素、系统剪贴板和线上 provider 分别记录 unverified。

摘要驱动参数依次为新证据目录、模式、CLI、扩展安装根。模式取 native、native-fullscreen、codex、codex-fullscreen，每项均包含热 `/resume` 和冷 `--resume`。补丁版检查 task 可搜、隐藏正文不可搜及历史字节不变。native 加 `--cwd-cases` 补验启动 cwd 未信任扩展不加载、选择前无生命周期，以及缺失 cwd 的 Continue/Fork/Cancel。

```bash
node scripts/pi152-patched-verify.mjs run conda run --no-capture-output -n codex-py312 python extensions/skill-mentions/__tests__/resume-summary-driver.py .tmp/resume-native native node_modules/.bin/pi . --cwd-cases
```

原版复验把 launcher 换成带 PI152_RUNTIME 的 `pi152-verify.mjs run`，regions 加 `--original`，摘要加 `--stock-summary`。原版保留协议正文显示和可搜索正文，不能报告为投影通过。

## Measure and clean up

先读 [performance](performance.md) 及 benchmark-checklist，写待证伪主张并检查机器负载。禁止并行运行构建、测试或其他本任务测量。CPU 脚本必须在补丁运行树执行，裸导入按脚本目录解析，改变 cwd 无法修正根脚本的依赖来源。

```bash
node scripts/pi152-patched-verify.mjs run node --expose-gc scripts/local-refresh-cpu.mjs --profile=pi152 --baseline=/absolute/new-stock/node_modules/@earendil-works/pi-tui --baseline-agent=/absolute/new-stock/node_modules/@earendil-works/pi-coding-agent --baseline-lock=/absolute/new-stock/pnpm-lock.yaml --mode=regular
```

同步沿用 0/200/1000、50 预热、7×320、三轮×双模式。原生另加 `--interval=32 --pairs=200,1000 --workloads=animation-and-rate --frames=40 --samples=5`，双模式。每个计时请求须实际完成一帧。保留所有失败、异常及样本，仍使用动态 ≥30% 和正常/未用 API ≤max(10%,0.1ms/帧) 的预算。两侧四包/扩展/主题/补丁/锁来源和输出、光标、layout 等价均须记录。独立 profile 不计入正式数字。

按主 skill Cleanup 检查每个 PTY 的 PID、进程组和监听端口。摘要驱动的 PID 位于 journey.json。运行树及性能样本留证，任务创建的服务和进程全部停止。复查全局 Pi 的路径和字节 hash。
